# Аудит рефакторинга репозитория zeshicast

## 📊 Базовое состояние (Baseline)
Перед началом аудита были выполнены проверки `cargo fmt`, `cargo clippy` и `cargo test`:
- **Форматирование:** Проверка `cargo fmt --check` пройдена успешно.
- **Статический анализ:** `cargo clippy` не выявил предупреждений или ошибок (выполнено с `-D warnings`).
- **Тесты:** Успешно пройдено 100 юнит-тестов (`100 passed; 0 failed`).
Кодовая база находится в хорошем техническом состоянии, однако обнаружен ряд архитектурных возможностей для улучшения производительности, безопасности и читаемости кода.

## 🛠 Выявленные возможности для рефакторинга (Opportunities)

### RUST-001: Замена монолитного метода `search` на реестр провайдеров (Registry Pattern)
- **Location:** `src/app.rs` (метод `search`), `src/search/mod.rs`.
- **Evidence:** В методе `search` происходит ручной вызов `.extend()` для более чем 20 различных провайдеров (AppsProvider, CommandsProvider, MediaProvider и т.д.) внутри одной функции на 140 строк. Несмотря на существование трейта `SearchProvider`, он не используется для динамической маршрутизации.
- **End state:** Инициализация вектора активных провайдеров `Vec<Box<dyn SearchProvider>>` при загрузке (на основе настроек) и итерация по нему в методе `search` с использованием `flat_map` или цикла.
- **Coupled changes:** Изменение сигнатур провайдеров для безопасного использования в `Box<dyn SearchProvider>` (возможность передачи состояния `&self`), удаление ручных проверок `if self.preference_enabled(...)` из метода `search`.
- **API/behavior impact:** Внутренний рефакторинг. Поведение поиска не изменится, но добавление новых модулей поиска станет декларативным.
- **Risk/value:** Низкий риск / Высокая ценность. Уменьшает цикломатическую сложность центрального метода приложения.

### RUST-002: Оптимизация аллокаций строк (String) в структурах `Action` и `ExecutionRequest`
- **Location:** `src/action.rs` (`Action`, `ExecutionRequest`, `ActionKind`), `src/app.rs`.
- **Evidence:** В структурах широко используются типы `String` для полей `title`, `subtitle`, `category`, `icon_name`. При каждом вводе символа в строку поиска провайдеры генерируют сотни `Action`, аллоцируя и клонируя строки, что создает нагрузку на аллокатор.
- **End state:** Использование `std::borrow::Cow<'a, str>` или `Arc<str>` (cretae `smol_str` или `compact_str`) для строковых полей, которые редко изменяются, но часто клонируются.
- **Coupled changes:** Все реализации `SearchProvider`, возвращающие `Vec<Action>`, и макросы конструирования `Action`.
- **API/behavior impact:** Существенное снижение потребления памяти и времени отклика UI при поиске.
- **Risk/value:** Средний риск (изменение контракта владения) / Высокая ценность (производительность UI).

### RUST-003: Устранение зависимости от внешнего процесса `tar` при импорте/экспорте конфига
- **Location:** `src/config.rs` (функции `import_config`, `export_config`, `validate_archive_members`).
- **Evidence:** Для работы с архивами используется `std::process::Command::new("tar")`. Проверка безопасности архива (`validate_archive_members`) парсит вывод `tar -tzf`, что крайне хрупко и подвержено атакам типа "Command Injection" и "Path Traversal" (особенно если имена файлов содержат спецсимволы или переносы строк).
- **End state:** Использование нативных крейтов `tar` и `flate2` для распаковки и запаковки архивов с программной валидацией путей.
- **Coupled changes:** Добавление зависимостей `tar` и `flate2` в `Cargo.toml`. Удаление вызовов `Command::new("tar")`.
- **API/behavior impact:** Повышение кроссплатформенности, устранение зависимости от ОС, полная изоляция от shell-инъекций.
- **Risk/value:** Низкий риск / Высокая ценность (закрытие потенциальных уязвимостей (Security)).

### RUST-004: Использование крейта `tempfile` для безопасной атомарной записи
- **Location:** `src/config.rs` (функция `write_file_atomic`).
- **Evidence:** Приложение реализует собственную атомарную запись файлов: генерирует имя вида `.{file_name}.tmp-{pid}-{nanos}`, пишет туда и делает `fs::rename`. При ошибке временный файл удаляется блоком `if result.is_err() { ... }`.
- **End state:** Использование крейта `tempfile::NamedTempFile` (с его методом `persist`), который берет на себя безопасное создание уникальных файлов и их автоматическое удаление при панике или ошибке.
- **Coupled changes:** Обновление функции `write_file_atomic`.
- **API/behavior impact:** Исключение утечек временных файлов при паниках.
- **Risk/value:** Низкий риск / Средняя ценность. Идиоматичный подход к файловым операциям.

### RUST-005: Строгая типизация (Stringly Typed) элементов буфера обмена
- **Location:** `src/app.rs` (`clipboard_history: Vec<String>`, `CLIPBOARD_IMAGE_PREFIX`), `src/storage.rs`.
- **Evidence:** Текст и изображения в истории буфера обмена хранятся как `String`. Изображения маркируются специальным строковым префиксом `\u{1}zeshicast-image:`. Метод `classify_clipboard_text` парсит строки для определения типа.
- **End state:** Введение перечисления `enum ClipboardItem { Text(String), Image(PathBuf) }`. Сохранение типа отдельным столбцом `item_type` в базе данных SQLite.
- **Coupled changes:** Схема БД (`storage::migrate`), логика загрузки/сохранения в `app.rs`, маппинг в UI.
- **API/behavior impact:** Изменение схемы локальной базы данных. Код становится типобезопасным и защищенным от случайных совпадений префикса.
- **Risk/value:** Средний риск (требует миграции БД) / Высокая ценность.

### RUST-006: Обратная связь в UI для фоновых асинхронных задач
- **Location:** `src/action.rs` (`run_execution_request`).
- **Evidence:** При выполнении долгих HTTP-запросов (перевод, AI), задача отправляется в `std::thread::spawn`. В случае ошибки используется `eprintln!("http request failed")`, что абсолютно невидимо для пользователя графического интерфейса.
- **End state:** Использование `mpsc::Sender` или системы событий (например, GTK channels / async runtime), чтобы уведомлять основной поток о статусе фоновых задач (успех/ошибка). Вызов `push_notification` для отображения ошибки пользователю.
- **Coupled changes:** Сигнатура `run_execution_request` должна принимать контекст отправки сообщений или напрямую интегрироваться с подсистемой уведомлений.
- **API/behavior impact:** Улучшение отзывчивости интерфейса, пользователи будут получать оповещения при сбое сети или ошибках AI/перевода.
- **Risk/value:** Средний риск / Высокая ценность (UX).

## 📦 Рекомендуемые пакеты внедрения (Implementation Batches)

1. **Пакет 1: Безопасность и надежность (Security & Robustness) — RUST-003, RUST-004**
   - Внедрение нативных библиотек `tar`, `flate2` и `tempfile`. 
   - Избавит кодовую базу от вызовов `std::process::Command` для системных утилит и устранит уязвимости, связанные с путями в файловой системе.

2. **Пакет 2: Архитектура и модульность (Architecture) — RUST-001**
   - Рефакторинг модуля поиска для использования `Vec<Box<dyn SearchProvider>>`.
   - Значительно упростит метод `app.search` и подготовит платформу для подключения плагинов/провайдеров в будущем.

3. **Пакет 3: Производительность и типы (Performance & Typing) — RUST-002, RUST-005**
   - Переход на умные указатели для строковых данных в `Action` (снижение CPU и Memory Overhead).
   - Миграция схемы SQLite для буфера обмена и введение `enum ClipboardItem`.

4. **Пакет 4: Пользовательский опыт (UX/Async) — RUST-006**
   - Интеграция фоновых потоков `std::thread::spawn` с центральной системой уведомлений, чтобы ошибки не терялись в `stderr`.
