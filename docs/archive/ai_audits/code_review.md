## 🌟 Общее впечатление и что сделано отлично (Praise)
Репозиторий `zeshicast` представляет собой отлично структурированный проект лаунчера на Rust. Код разбит на логичные и изолированные модули (`search`, `services`, `ui`, `action`), что сильно упрощает навигацию и поддержку.

Особенно хочется отметить:
- **Внимание к безопасности при импорте конфигов:** В [`src/config.rs`](../../src/config.rs) реализована хорошая защита от распаковки архивов (проверки на path traversal `../`, запрет абсолютных путей и предотвращение атак через symlink-и).
- **Экранирование шелл-команд:** В [`src/placeholders.rs`](../../src/placeholders.rs) реализована умная функция `expand_placeholders_shell`, которая корректно оборачивает параметры в POSIX-кавычки, предотвращая базовые RCE-инъекции.
- **Отзывчивость UI:** Грамотное использование [`src/services/poll_cache.rs`](../../src/services/poll_cache.rs) для вынесения тяжелых системных вызовов (сбор статистики сети, аудио через `ip` и `wpctl`) в фоновый поток, чтобы не блокировать главный цикл GTK.

## 🔴 Blockers (Критичные проблемы) — ✅ ИСПРАВЛЕНО

### 1. [x] Security: Race Condition / TOCTOU при сохранении конфигов — ✅ ИСПРАВЛЕНО
- **Location:** [`src/config.rs`](../../src/config.rs) (функция `write_file_atomic`)
- **Проблема:** В функции `write_file_atomic` сначала создавался временный файл, и лишь затем менялись его права доступа:
  ```rust
  let mut file = fs::OpenOptions::new()
      .write(true)
      .create_new(true)
      .open(&temp_path)?;
  set_file_mode(&file, mode)?; // Устанавливается 0o600
  ```
  Файл изначально создавался с системным `umask` (часто `0644` или `0666`), и только после этого его права урезались до `0600`. Это создавало TOCTOU уязвимость.
- **Статус исправления:** Использован крейт `tempfile::Builder` и метод `PermissionsExt::from_mode(mode)` до записи данных, с помощью `.persist(path)` атомарно переносящий файл. Права `0600` присваиваются атомарно при создании.

## 🟡 Suggestions (Предложения по улучшению) — ✅ ИСПРАВЛЕНО

### 1. [x] Performance: Системные вызовы вместо чтения процессов через `fork+exec` — ✅ ИСПРАВЛЕНО
- **Location:** [`src/services/system_stats.rs`](../../src/services/system_stats.rs) (`read_root_disk_usage`)
- **Проблема:** Вызывался внешний процесс `Command::new("df").args(["-kP", "/"])`. Использование `fork+exec` для получения статистики диска — тяжелая операция.
- **Статус исправления:** Заменено на нативный системный вызов `rustix::fs::statvfs("/")`.

### 2. [x] Security: Защита от "двойного экранирования" плейсхолдеров — ✅ ИСПРАВЛЕНО
- **Location:** [`src/placeholders.rs`](../../src/placeholders.rs) (`expand_placeholders_shell`)
- **Проблема:** Если пользователь в конфигурационном файле сам обернет плейсхолдер в кавычки (`command = "echo '{{query}}'"`), итоговая строка подставлялась с лишними одинарными кавычками.
- **Статус исправления:** Добавлено поглощение внешних одинарных кавычек при расширении плейсхолдеров в shell-режиме и покрыто юнит-тестом `test_redundant_single_quotes_in_shell_placeholders`.

### 3. [x] Performance: Устранение дрифта таймера в фоновом поллинге — ✅ ИСПРАВЛЕНО
- **Location:** [`src/services/poll_cache.rs`](../../src/services/poll_cache.rs)
- **Проблема:** Цикл фонового потока вызывал `std::thread::sleep(Duration::from_secs(1))` *после* выполнения работы, вызывая дрифт таймера.
- **Статус исправления:** Рассчитывается `start = Instant::now()` и опрашиваемый поток засыпает на `target_interval.checked_sub(elapsed)`.

### 4. [x] Maintainability: Вызов бинарников напрямую вместо shell-строк — ✅ ИСПРАВЛЕНО
- **Location:** [`src/search/windows.rs`](../../src/search/windows.rs)
- **Проблема:** Команды фокуса окон формировались как shell-строки (`ActionKind::Shell`) с пробросом в `sh -c`.
- **Статус исправления:** Переведено на `ActionKind::Command(ProcessCommand::new("niri", ...))`, `ProcessCommand::new("hyprctl", ...)`, `ProcessCommand::new("swaymsg", ...)`.
