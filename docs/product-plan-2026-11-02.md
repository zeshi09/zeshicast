# План улучшения продукта (2026-11-02)

**Основание:** `docs/product-review-2026-11-02.md` (ревью + сравнение с Raycast 2.0
и Vicinae v0.29.2).
**Заменяет:** `docs/product-plan-2026-09-19.md`. Невыполненные шаги оттуда
перенесены сюда с новыми ID; соответствие — в разделе «Перенос из плана
2026-09-19». Стратегия прежняя: **A** «безопасный Raycast для Linux» +
**B** «Linux control center». Изменился **порядок**: сначала то, что
пользователь видит в первые 5 минут.

**Принципы (без изменений):** fail-closed; одна точка исполнения (`execute` +
`ExecutionTicket`), ни одного `Command::new` мимо `crate::process`; ни одного
изменения поведения без теста; шаг = один коммит = один проверяемый результат;
никакой телеметрии; никаких сетевых вызовов без явного действия пользователя.

**Оценки:** S — 1–3 дня, M — 1–2 недели, L — месяц+.

**Проверка каждого шага (Definition of Done):**

1. `cargo fmt --check`;
2. `cargo clippy --all-targets -- -D warnings` и `cargo test` в трёх
   конфигурациях: без фич, `--features desktop`,
   `--features gui,layer-shell` (через `nix-shell shell.nix`);
3. для шагов с утверждениями в `docs/security.md` — маркер `<!-- test: … -->`
   и зелёный `documented_invariants_have_the_tests_they_name`;
4. строка в `CHANGELOG.md` (после Q4.1) в разделе `Unreleased`;
5. для UI-шагов — ручная проверка в niri по чек-листу шага.
