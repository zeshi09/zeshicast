## 1. 🔴 БЛОКЕРЫ

### B-1. Обход `permissions = ["shell"]` через форму аргументов (подтверждено вручную)

`src/search/commands.rs:377-433`, `src/app.rs:1025-1066`, `src/ui/launcher.rs:412,2039`

Проверка capability есть **только** в ветке «все аргументы заданы»:

```rust
// commands.rs:386 — проверка есть
if has_capability(&entry.capabilities, Capability::Shell) { … }
// commands.rs:402-423 — ветка формы, проверки НЕТ
} else { let form = ActionForm { … command: form_command(entry) … }; }
```

`ActionForm` вообще не несёт capabilities (`src/action.rs:53-62`), риск остаётся `ActionRisk::Normal` (`commands.rs:430` требует `missing.is_empty()`), а `run_form_action` вызывает исполнитель напрямую, минуя `ExecutionPolicy`:

```rust
// app.rs:1044-1049
ActionFormCommand::Shell(command) => {
    let command = expand_placeholders_shell(command, &context);
    run_execution_request(ExecutionRequest::Shell { … });   // ни policy, ни has_capability
}
```

**Воспроизведение:** команда без `permissions`, с одним required-аргументом. Набрать только ключевое слово → открывается форма → заполнить → «Run» → `sh -c` выполняется. Документация (`docs/security.md`, раздел Extension Permissions) утверждает обратное.

**Фикс:** (1) проверка capability в ветке формы; (2) `ActionRisk::Shell` для форм shell/json-режима; (3) `run_form_action` через `run_action_with_policy`/единый choke point; (4) регрессионный тест «форма не создаётся без `shell`».

### B-2. Инъекция через плейсхолдер внутри авторских одинарных кавычек (подтверждено вручную)

`src/placeholders.rs:83-108`

Контекст определяется **только** для двойных кавычек:

```rust
let inside_double_quotes = shell_escape && is_inside_unclosed_double_quotes(&output);
```

Экранирование корректно, если плейсхолдер стоит вне кавычек или внутри `"…"`. Но не внутри уже открытой одинарной кавычки с другим текстом:

Шаблон `xdotool type 'clip: {{clipboard}}'`, в буфере обмена `$(touch /tmp/pwned)`:

```text
xdotool type 'clip: '$(touch /tmp/pwned)''
```

Авторская `'` закрывается **вставленной** кавычкой, payload оказывается вне кавычек → command substitution выполняется. Флаг `xdotool type 'clip: {{clipboard}}'` — естественный способ написать команду; README прямо учит авторов не квотировать плейсхолдеры, но `'текст {{x}}'` выглядит безопасно и не является таковым. `docs/security.md` («Placeholder Handling») гарантирует защиту от `$(...)` — гарантия не выполняется.

**Фикс:** добавить симметричный `is_inside_unclosed_single_quotes()`; при `inside_single_quotes` вставлять `value.replace('\'', "'\\''")` без внешних кавычек; не схлопывать «обёртку». Тест: `expand_placeholders_shell("xdotool type 'clip: {{clipboard}}'", ctx)` должен давать литерал.

### B-3. `child.wait()` без таймаута после успешного JSON-RPC → вечное зависание UI (подтверждено вручную)

`src/services/extension_protocol.rs:139-160`

```rust
let line_result = rx.recv_timeout(Duration::from_millis(effective_timeout));
let line = match line_result {
    Ok(Ok(line)) => { let _ = child.wait(); let _ = reader_handle.join(); line }   // <-- без таймаута
```

Расширение, которое пишет одну строку валидного JSON и затем «висит» (sleep, debugger, deadlock), заставляет `wait()` блокироваться навсегда. Всё это — на GTK-main-loop (`ExtensionsProvider::search`), т.е. **вечный фриз лончера**. Таймаут-гард обходится ровно тем сценарием, от которого он защищает.

Дополнительно: ветка `Failed to write to stdin` (`:126-129`) возвращает ошибку, **не убивая и не ожидая** ребёнка → утечка процесса + зомби. Чтение ответа не ограничено по размеру (`read_line` в неограниченный `String`).

**Фикс:** после получения строки — `try_wait` в цикле до общего дедлайна, затем `kill()`; все пути выхода через общий guard (RAII `ChildGuard`); лимит на длину строки.

### B-4. Строка калькулятора: не вычисляет, «мёртвая» по Enter и сдвигает индексацию действий (подтверждено вручную)

`src/ui/launcher.rs:1327-1329, 1428-1493, 2433-2471`

```rust
if query.starts_with('=') { list.append(&calc_result_row(expr)); }   // строка НЕ попадает в `results`
…
*results.borrow_mut() = displayed_actions;                            // только действия поиска
```

```rust
fn evaluate_expr(expr: &str) -> String { … safe }   // возвращает саму строку: «Evaluate» не вычисляет
```

Последствия для запроса `=2+2`:

1. в слоте результата показывается `2+2`, а не `4` (дизайн-спека ожидает результат);
2. Enter/Ctrl+Enter на строке ничего не делают — `results` пуст (`action_index_for_row` → `results.get(0)` → `None`), бейдж «⌃C» врёт;
3. **сдвиг индексации:** `action_index_for_row` считает все selectable-строки, включая calc-строку. Если на тот же запрос что-то нашлось (например, один `=` матчит URL вкладок браузера), подсветка строки *n* запускает `results[n]`, т.е. действие **под** подсвеченным; последнее действие недостижимо. В комбинации с `ProcessKill` это запуск не того действия.

**Фикс:** строить настоящий `Action` (`Calculator::new(expr).parse()` + `format_number`) и класть его в `results`, либо сделать строку `set_selectable(false)` и обрабатывать её отдельной ветвью в `handle_key`.

### B-5. Исполняемые файлы из `commands` манифеста расширения: spawn на каждое нажатие клавиши + обход capability/подтверждения (подтверждено вручную)

`src/search/mod.rs:295-303`, `src/search/extensions.rs:8-45`, `src/services/extension_protocol.rs:100-179`

`ExtensionsProvider::search` для каждого пути из `manifest.commands` вызывает `search_extension` → `call_json_rpc` → `Command::new(path).spawn()`. То есть **каждое нажатие клавиши** = fork+exec+ожидание до 400 мс на каждую запись, синхронно на UI-потоке (debounce отсутствует, см. M-1).

При этом возвращённые элементы жёстко получают `risk: ActionRisk::Normal` (`extensions.rs:34`), а `ActionKind::Launch(id)` превращается в `ExecutionRequest::Shell` → `sh -c` (`action.rs:362`). Итог: результат расширения выполняется **без проверки capability и без диалога подтверждения**, хотя документация обещает обратное. `manifest.capabilities` гейтит только `scripts`, но не `commands`.

Дополнительно: `manifest_paths` (`extensions.rs`) пускает любой относительный файл, а не только `.toml`, как описано в README.

**Фикс:** прогонять элементы расширения через тот же гейт, что и JSON-команды (`parse_json_action_kind`), форсировать `ActionRisk::Shell` для `Launch`; ограничить `commands` файлами `.toml`; вынести RPC с UI-потока.

### B-6. Аргументы argv-режима и формы скриптов не проходят ни capability, ни подтверждение (подтверждено вручную)

`src/search/commands.rs:381-383,430-434`, `src/search/scripts.rs:392-393`, `src/ui/launcher.rs:2549`

* `CommandMode::Argv` не требует `shell` и получает `ActionRisk::Normal` (явное исключение `entry.mode != CommandMode::Argv`). TOML с `program = "/bin/sh", args = ["-c", "curl … | sh"]` исполняется мгновенно и молча. Обоснование в `docs/security.md` («argv не вызывает `sh -c`») — не граница безопасности: `program` выбирает автор манифеста.
* Скрипт с объявленными аргументами открывается через форму, а форма ответвляется **до** обработки риска (`launcher.rs:412`) → `@raycast.needsConfirmation false` в шапке скрипта полностью отключает подтверждение.

**Фикс:** ввести единый choke point исполнения с явным «receipt» (capability + подтверждение) и провести через него argv, формы, скрипты и JSON-действия.

## 3. 🟡 MINOR / NIT (сгруппировано)

* **Дублирование логики риска:** две разные `secondary_action_risk` — `app.rs:531-541` (`RunInTerminal => Normal`) и `ui/launcher.rs:2346-2354` (`=> action.risk`). Поведение CLI и GUI расходится: «Run in Terminal» из CLI выполнит shell-команду **без** подтверждения. Это уже случившаяся деградация, а не гипотеза.
* **CLI:** `run_action_menu` (`main.rs:118-121`) игнорирует возвращённый `ExecutionDecision` → Enter на shell-действии молча ничего не печатает. `parse_cli_args` перехватывает `--export`/`--import` в любом месте argv, включая текст запроса (`zeshicast shell --export …`).
* **`lib.rs` как god-module:** 188 re-export'ов + 60 inline-тестов + `#[cfg(test)] pub(crate) use` для доступа к приватным символам — цена: любое изменение внутреннего API ломает «публичный» фасад, тесты зависят от формы экспорта.
* **Мёртвый/полу-мёртвый код:** `show_preferences_editor`, `show_extension_browser` (дубли), `generate_simple_uuid` (не документирован), `fa_icon` (обещанный fallback не реализован), `JsonCommandAction`/`CAPABILITY_DENIED`/`initialize`/`list_commands`/`execute` под `#[allow(dead_code)]`, `SCORE_*` константы с `#[allow(dead_code)]`. `Cargo.toml` `#[allow(dead_code)]`-инвентарь стоит подчистить — он маскирует незавершённый рефакторинг (P3-1…P3-5).
* **Экран/UX:** `status_items` фактически игнорируется 1-секундным обновлением статус-строки; System Monitor NET читает хардкод `eth0`; фильтр процессов, сортировки CPU/MEM, per-row kill ×, тумблер Extensions — не работают; подсказка Ctrl+Shift+F открывает Fonts; `move_selection(0)` — потенциальный бесконечный цикл; футер не учитывает невыделяемые строки; `expire_timeout_ms == 0` должен означать «никогда», а не 8 с; `font_desc` собирается без экранирования.
* **Markdown → Pango:** при пересечении `**`/`*` спанов генерируется несбалансированная разметка → сообщение не рендерится вовсе. Экранирование `&<>` при этом корректно (инъекции разметки нет).
* **`search/browser_tabs.rs`:** читает файл сессии, который современный Firefox больше не пишет (ветка мертва), при этом опрашивается на каждом нажатии; закладки показываются как вкладки.
* **`format_number`:** для больших значений молча возвращает i64-сатурацию; `find`-нотация `{}`? нет — только exact.
* **PIDs:** kill по PID без проверки старта процесса (переиспользование PID) — в System Monitor и в `proc`.
* **`deny.toml`:** конфиг есть и используется CI — но `[advisories] ignore = []` и нет `[bans]`-исключений; `flake.lock` в `.gitignore` (файл есть, но не в git) → `nix develop`/CI в чистом окружении пере-резолвит nixpkgs (в этой сессии именно это и уронило сборку).
* **Ошибки/логи:** нет `log`-фасада, только `println!`/`eprintln!`; секреты при этом не печатаются (проверено: `spawn_shell` печатает только `<command>`), но диагностика для демона в journald слабая. `export/import` при ошибке печатают сообщение и **возвращают код 0**.
* **`~` не раскрывается** для `script_dirs` (`search/scripts.rs`), при этом значение по умолчанию в документации — `~/…`.

## 4. ✅ Что сделано хорошо (важно для контекста)

* **Placeholder-механика** (за вычетом B-2): `shell_quote` (`'\''`) и `double_quote_escape` корректны и сбалансированы даже на значениях, оканчивающихся на `'`, `\`, `"`; сканнер контекста учитывает вложенные кавычки и backslash; есть регрессионные тесты на реальные находки прошлых ревью (FINDING 1/2).
* **Валидация tar-импорта:** до распаковки отвергаются absolute-пути, `..`/RootDir-компоненты, symlink и hardlink члены, требуется единый корень `zeshicast/`; распаковка в staging + повторная проверка symlink + атомарная замена с откатом. Проверка «FIFO/Char/Block попадают в ветку обычного файла» — тоже выполнена.
* **Атомарная запись файлов** (`write_file_atomic`): tempfile в том же каталоге, режим 0600 до записи, `sync_all`, `persist` (rename), `fsync` каталога; symlink не перезаписывается по цели (есть тест).
* **SQLite-слой:** только параметризованные запросы, ни одно значение из БД не используется как путь, миграции с версией схемы, дедупликация при миграции, файл БД 0600 (тесты есть). `prune` картинок ограничен `.png` внутри кэша.
* **Секреты не утекают в stdout/stderr/journald:** `spawn_shell`/`spawn_command` печатают только имя программы; ошибки HTTP не содержат ключей; `write_preferences`/БД — 0600.
* **Уведомления:** `hints`/`image-data`/`actions` не парсятся вообще; `child_value(i).get::<T>().unwrap_or_default()` не паникует на мусоре; `expire_timeout` клампится; хранилище дедуплицируется и ограничено 100 записями; текст из уведомлений нигде не становится командой/URL/путём.
* **`poll_cache`** — правильный паттерн (worker + snapshot-кэш) уже применён к network/audio; осталось распространить на media/processes/compositor.
* **Архитектурная идея** «один lib + headless CLI + GTK-демон» рабочая; сервисный слой не тянет GUI в CLI.

## 5. Архитектурный вердикт

* **God-module/god-object/god-function:** `lib.rs` (188 re-export'ов, 60 inline-тестов), `app.rs` (1520 строк, ~60 методов, 16 полей), `ui/launcher.rs` (3110 строк, `build_ui` — 1057 строк, сигнатуры на 20-32 аргумента). Это главный тормоз разработки: любое изменение UI стоит дорого, тестировать нечего.
* **Два бинарника расходятся уже сейчас** (не «потом»): `#[cfg(feature = "gui")]` разрывает функциональность CLI — JSON-команды не выполняются (`run_json_command` под `gui`), `media`-действия молча ничего не делают (`services/media.rs:42-49`), захват stdout скриптов отсутствует. Это уже баги, а не дрейф.
* **Нет единой точки исполнения.** `run_execution_request` вызывается из 4 мест напрямую, рядом живут `run_command_request`/`run_shell_request`/`run_action_*`/`run_form_action` — и именно из-за этого существуют B-1 и B-6. Единый choke point с явным capability-receipt закрывает 5 находок одним рефакторингом.
* **Нет стратегии ошибок и логирования.** `Result`/panic/`let _ =` смешаны, `let _ =`/`.ok()` глушат миграции и chmod; для демона нет структурного журнала.
* **Поиск на UI-потоке** — системная архитектурная проблема (M-1…M-4, M-6): провайдеры делают IO (fork/exec, файлы, D-Bus) прямо в `search()`. `poll_cache` показывает, что команда умеет делать правильно.
