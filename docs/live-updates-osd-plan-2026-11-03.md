# План: живые данные и OSD громкости/яркости (2026-11-03)

Запрос владельца: данные в палитре должны быть свежими сразу при открытии
(сейчас время и громкость обновляются с заметной задержкой), и нужна
анимированная OSD при изменении громкости и яркости, как уже есть тост
«скопировано в буфер».

## Почему сейчас задержка

| Что видно | Причина в коде |
| --- | --- |
| Время в статус-строке «догоняет» после открытия | `status_strip.rs::start_clock` тикает раз в секунду и пропускает тики, пока окно скрыто; при показе нет немедленного `refresh()` — до 1 с старого времени |
| Громкость, сеть, медиа обновляются через секунду-полторы после открытия | `poll_cache` при скрытом окне спит (`set_active(false)`, P3.3: скрытая палитра не форкает); после показа первый тик — через сон до 1 с, а сам тик последовательно форкает `wpctl` ×3, `nmcli`, `ip`, MPRIS — ещё сотни мс |
| Громкость меняется клавишей, а в палитре — с задержкой | громкость только опрашивается (`wpctl` раз в секунду); событий об изменении нет. Клавиши в niri зовут `wpctl` напрямую, zeshicast о нажатии не знает |
| Яркость | на этой машине (десктоп) нет `/sys/class/backlight`, `ddcutil` не установлен, модуль `i2c-dev` не загружен: `brightnessctl set 10%+` из конфига niri меняет яркость светодиода (NumLock), а не монитора |

## Идея

1. **Событие — триггер, утилита — истина.** Как в буфере (Q6.4): дешёвый
   источник событий говорит «что-то изменилось», после чего читается одно
   точное значение. Источники событий живут и при скрытой палитре (они не
   форкают каждую секунду, а ждут), опрос остаётся только для того, у чего
   событий нет (CPU, память, процессы) и только при видимом окне.
2. **Показ = немедленное обновление.** При показе окна: сразу `refresh()`
   часов, сразу один внеочередной тик поллера (без сна), значения из
   событийного кэша — мгновенно.
3. **OSD знает значение без опроса, когда меняет его сам.** Команды
   `zeshicast-gtk --volume +5` / `--brightness -10` (через уже существующий
   IPC демона, как `--toggle`) меняют значение и показывают OSD с известным
   новым уровнем — без задержки опроса. Привязать их к клавишам в niri
   вместо прямого `wpctl`. Изменения из других мест (pavucontrol, кнопки
   гарнитуры) ловит событийный источник и тоже показывает OSD.

## Шаги

| ID | Что делать | Тест | Критерий приёмки | Цена |
| --- | --- | --- | --- | --- |
| L1 ✅ | Часы: `refresh()` в момент показа окна; тик выровнен на границу минуты (сейчас — каждую секунду с пропусками) | Тест: показ окна вызывает обновление; расчёт задержки до следующей минуты | Время верное в первом кадре после открытия | S |
| L2 ✅ | Поллер: будить по показу окна (Condvar вместо `sleep`), первый тик — сразу; порядок: дешёвое (часы, раскладка, кэш событий) раньше дорогого | Тест: `set_active(true)` будит поток без ожидания интервала | Статус-строка и дашборд свежие в первые ~100 мс после открытия | S |
| L3 ✅ (`pw-dump --monitor`: в простое молчит; первый дамп ~450 КБ один раз при старте) | Аудио по событиям PipeWire: спайк — `pw-dump --monitor` (просто, но первый вывод ~450 КБ полного графа) против крейта `pipewire` (нативно, новая системная зависимость). Событие об изменении узла `@DEFAULT_AUDIO_SINK@`/`SOURCE@` → одно чтение `wpctl get-volume` → кэш + сигнал в UI | Тесты разбора событий на фикстурах; дебаунс (одно чтение на серию событий) | Громкость в палитре меняется в пределах ~50 мс после нажатия клавиши; при скрытом окне нет форков раз в секунду | M |
| L4 | Остальные источники событиями вместо опроса: NetworkManager (`PropertiesChanged`/`StateChanged` по D-Bus), UPower (батарея), MPRIS `PropertiesChanged` (медиа), раскладка и рабочие столы — уже есть `niri msg event-stream` | Тесты на фикстурах сигналов; отсутствие сервиса → тихий откат на опрос | Сеть/медиа/батарея меняются без ожидания тика | M |
| O1 ✅ (вживую не смотрел — нужен установленный 0.3+) | OSD-виджет уровня: слой-оверлей (layer-shell), иконка + полоса уровня + число, анимация появления (fade + сдвиг), плавное изменение полосы при серии нажатий (одна OSD обновляется, а не плодится), автоскрытие ~1.2 с; стиль из дизайн-системы; позиция и включение — настройками (`osd_volume`, `osd_brightness`, `osd_position`) | Тест модели OSD: коалесценция серии, таймер скрытия, mute → отдельная иконка; снимок разметки | Нажатие громкости показывает плавную OSD; серия нажатий — одна OSD с анимированной полосой | M |
| O2 ✅ | `zeshicast-gtk --volume <+N|-N|N|mute>` и `--mic-mute`: через IPC демона, меняют громкость `wpctl` (с ограничением 0–100 % или выше по настройке) и показывают OSD с новым значением; инструкция и генератор биндингов для niri/Hyprland/sway (как Q1.6) | Тесты разбора аргументов и вычисления нового уровня; биндинги для трёх композиторов | Клавиши громкости через zeshicast: OSD появляется в первом кадре | S |
| O3 ✅ (не при открытой палитре; микрофон — только mute) | OSD по событию L3: изменение громкости извне (pavucontrol, гарнитура) тоже показывает OSD; своё изменение из O2 не показывается дважды | Тест: событие с тем же значением, что только что показано, не создаёт вторую OSD | Любое изменение громкости видно | S |
| B1 ✅ (только подсветка; запись через logind `SetBrightness`; на этом десктопе вживую не проверить) | Яркость: абстракция «источник яркости» — подсветка ноутбука (`/sys/class/backlight`, события udev `backlight change`) и внешние мониторы по DDC/CI (`ddcutil`; событий нет, только своё изменение из B2; запись 50–200 мс — в фоновом потоке, OSD показывается сразу с целевым значением) | Тесты разбора `ddcutil getvcp 10`/sysfs на фикстурах; нет устройств → понятное сообщение | Яркость меняется клавишей, OSD показывает уровень | M |
| B2 ✅ | `zeshicast-gtk --brightness <+N|-N|N>` + OSD, как O2; для DDC — очередь (быстрые нажатия сливаются в одну запись) | Тест слияния очереди | Серия нажатий не «догоняет» монитор секундами | S |

Порядок: L1 → L2 (быстрый эффект «свежо при открытии») → O1 → O2 (OSD громкости
по своим клавишам) → L3 → O3 → L4 → B1 → B2.

## Решения владельца (2026-11-03)

| Вопрос | Решение |
| --- | --- |
| Яркость | Пока только подсветка ноутбука (`/sys/class/backlight` + события udev). DDC/CI для внешних мониторов не делаем; в B1 остаётся точка расширения под него |
| Клавиши громкости | Перепривязать `XF86Audio*` в niri на `zeshicast-gtk --volume …` (строки для `config.kdl` готовлю я, конфиг правит владелец) |
| Вид OSD | Внизу по центру; показывается и при «Не беспокоить» (это обратная связь на нажатие) |
| Опрос без событий (CPU, память, процессы) | Только при видимом окне, с немедленным тиком при открытии |

С учётом решений B1 сужается: только подсветка; B2 — без очереди DDC.
На этой машине (десктоп без подсветки) OSD яркости проверить вживую нельзя:
только тестами на фикстурах sysfs.
